# V0.2 平台耦合审计（VES-056）

> 状态：审计完成；CI 已验证三平台编译，凭据运行时与实机验证待 VES-057/068
>
> 日期：2026-10-22
>
> 范围：`src/`、`src-tauri/src/`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`、`scripts/`、`tests/`
>
> 结论依据：静态审查 + Windows 本地运行；未在 macOS/Linux 构建或启动。

## 1. 结论

1. 文档编码、换行、Diff、建议状态机等核心业务逻辑没有平台分支，可保持平台中立。
2. 平台耦合集中在六类：凭据后端、原子保存、路径/文件语义、打包目标、窗口与快捷键文案、测试与发布脚本。
3. 阻断 V0.2 的剩余项：NSIS-only 打包（VES-061）与 Unix 保存语义（VES-058）；凭据后端已在本任务实现，macOS/Linux 运行时仍待实机验证。
4. 本次已建立统一适配层：
   - Rust：`src-tauri/src/platform.rs`（平台标识、谓词、路径展示）；
   - TypeScript：`src/lib/platform.ts`（平台标签解析、快捷键修饰键）；
   - 审计规则：平台判断集中在这两个模块，或在紧邻实现处使用窄范围 `#[cfg]`；业务层不得直接嗅探 UA 或拼平台字符串。

## 2. 审计方法

```bash
rg -n "cfg\(|std::env::consts|windows_sys|keyring|APPDATA|USERPROFILE|\.exe\b|WebView2|C:\\\\" \
```

## 4. 适配层合同

### 4.1 Rust

```rust
crate::platform::label()          // windows-x86_64
crate::platform::display_path(p)  // UI 展示路径
crate::platform::is_windows()     // 需要分支时使用
crate::platform::is_macos()
crate::platform::is_linux()
```

规则：

1. 新增 OS 分支必须优先放进 `platform.rs`；确需紧邻实现的，使用 `#[cfg(...)]` 并附测试或说明。
2. 业务模块不得直接读取 `std::env::consts` 拼平台字符串。
3. 不允许把 Windows 路径处理（`\\?\`、盘符、反斜杠）散落到业务层。

### 4.2 TypeScript

```ts
platformFamily(appInfo?.platform)      // 'windows' | 'macos' | 'linux' | 'unknown'
shortcutModifier(appInfo?.platform)    // '⌘' | 'Ctrl'
```

规则：

1. 平台来源只使用 `get_app_info`，不使用 UA / `navigator.platform`。
2. 快捷键文案、标题栏、菜单等差异统一经适配层生成。
3. 组件中不得写死 `win32`、`darwin` 或平台专属路径。
