## 4. 任务状态与交付追踪模板

状态：`Todo → Ready → In Progress → In Review → Done`，另有 `Blocked`。开发者每次只持有少量在途任务，避免界面、后端和数据迁移同时失控。

每项任务的实施记录至少包括：

```markdown
### VES-0XX｜任务标题

- 状态：Todo
- 关联需求：P-xxx / N-xx
- 前置：VES-xxx
- 修改模块/文件：
- 方案：
- 验收条件（来自 WBS）：
- 测试：
- 风险：
- PR/Commit：
- 负责人验收：通过 / 未通过
```

推荐把本表同步成 GitHub/GitLab Issues，每个任务一个 Issue。Issues 对应功能分支和测试；由 Agent 更新进度，但只有验证实际通过后才能标 `Done`。

## 5. 跨任务强制约束

1. **禁止数据损坏**：任何修改不能绕过文档保存、冲突检测与快照。
2. **禁止权限越界**：AI 任务只读/只写授权范围，模型返回永远不是可执行指令。
3. **禁止伪实现**：仅有 UI 按钮、模拟固定结果、未连接真实状态，不能算完成。
4. **禁止无证据通过**：任务必须附测试命令与结果。未运行写「未运行」，不能虚构。
5. **禁止默默改需求**：涉及功能范围、技术架构、数据模型重大变更，先提出 ADR/需求变更。
6. **禁止把秘密提交到仓库**：API key、私有文档、敏感日志不进入提交。
7. **保留本地文件独立性**：未安装 Vesrio 也能正常阅读 `.md` 内容。
