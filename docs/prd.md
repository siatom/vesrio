# 文屿 Vesrio｜产品创意与需求规格说明书

> 文档类型：产品创意书 / PRD（可作为开发基线）  
> 版本：v1.1（V0.2 路线调整）
>
> 日期：2026-10-22
> 产品名：**文屿 · Vesrio**  
> 定位：**Human-led, Agent-assisted Writing**——作者主导、Agent 协同的 AI 原生 Markdown 写作编辑器

## 0. 阅读约定与实施边界

- 需求采用 `P-xxx` 编号。V0.1 需求还需按 P0/P1 区分：P0 阻断发布，P1 可在负责人明确批准后延期；`SHOULD` 为下一版本目标，`LATER` 为方向性规划。
- 「作者」是实际操作者；「Agent」是可理解文档并提出建议的 AI 助手；「建议」是尚未落盘的候选修改；「应用」是用户确认后写入编辑器状态并保存的修改。
- 本文的 `V0.1` 指**单用户、本地优先、Windows 首发**的可用桌面 MVP。不代表正式发布日期。
- `V0.2` 定义为**独立的跨平台里程碑**（Windows / macOS / Linux），只做平台化，不新增写作功能；原 5.5 的 V0.2 SHOULD 功能已确认顺延 V0.3。详见 [V0.2 跨平台计划](./v0.2-cross-platform-plan.md) 与 [ADR-010](./adr/ADR-010-cross-platform-support.md)。
- 本文不是营销承诺；未列入 V0.1 的能力不得由 Coding Agent 擅自扩张实现。

## 1. 创意起点

### 1.1 问题

以聊天为中心的 AI 写作工具善于生成初稿，却经常破坏精细创作过程：

1. 选定一句话修改时，AI 往往重写整段甚至整篇，作者丧失原文控制。
2. 建议与原文分离，用户在聊天框和编辑器间复制粘贴，难以看清改了什么。
3. 文章讲求表达、语气、节奏、审美与逻辑，不存在普适的唯一「正确」改法。
4. 长文档经常反复迭代，单轮对话不易保留上下文、术语约定及个人风格。
5. 规范、论文、方案等专业内容需要严格遵守事实、证据与范围边界，不能因润色引入新事实。
6. 传统 Markdown 编辑器具备良好的写作手感，但缺少与原文融为一体的 Agent 协作层。

### 1.2 核心判断

**写作的主交互是直接编辑，AI 是伴随文字发生的、可控的协作，而不是替代编辑器的聊天入口。**

产品不能变成「写作领域的自动驾驶」。它是一个作者始终握有方向盘的创作工作台。

### 1.3 产品宣言

**Your words. Your voice.** 你的文字，你的声音。

Vesrio 是一款以 Markdown 为基础、以行内修改为核心、以 Agent 为深层理解能力的桌面写作工具。作者直接创作；Agent 理解上下文、提出候选修订、审查逻辑与一致性；作者决定最终表达。

## 2. 产品目标与非目标

### 2.1 目标

1. **无 AI 也好用**：基本 Markdown 编辑体验达到稳定、快捷、可专注写作的水平。
2. **修改不离开正文**：从选中到提出建议、对比和接受，无须复制粘贴。
3. **所有 AI 改动可控**：默认不直接覆盖；在明确范围和版本上形成可审查的补丁。
4. **了解上下文，尊重边界**：可阅读全文或项目背景，但只修改用户授权的文本范围。
5. **保留作者风格**：优先保持原意、术语、语言风格；把主观偏好变成可编辑配置。
6. **文档独立于产品**：`.md` 文件始终可被其它软件读取，扩展元数据独立保存。
7. **面向长期项目**：逐步提供跨章节逻辑、术语一致性、事实来源和版本管理。

### 2.2 明确非目标（V0.1）

- 不是通用 Coding IDE；不提供代码构建、调试和仓库自动编程 Agent。
- 不承诺完全自动成书、自动研究或无人监督的全篇重写。
- 不开发多人实时协作、云同步、账号体系、付费订阅或手机端。
- 不实现联网检索、复杂 RAG、向量数据库、自进化训练、多 Agent 编队。
- 不实现完整 Word/WPS 格式兼容或复杂桌面出版（DTP）。
- 不以「消除 AI 痕迹」为目标；作者身份、引用与事实核查始终优先。

## 3. 用户与典型场景

| 人群 | 核心任务 | 最主要痛点 | Vesrio 的价值 |
| --- | --- | --- | --- |
| 技术与规范编写者 | 技术规范、需求说明、方案、验收材料 | 专业语义不能变；规范措辞和章节要一致 | 局部精简、术语约束、章节逻辑检查 |
| 研究与知识工作者 | 论文、研究报告、调研综述 | 论证逻辑、证据来源和修订过程重要 | 结构检查、证据提醒、可追溯修改 |
| 作者与长文写作者 | 书籍、随笔、博客、长篇文章 | 个人文风易被模型抹平 | 语气保留、局部试写、多版本比较 |
| 内容编辑 | 审稿、校对、品牌文案 | 大量微调、统一编辑规范 | 差异审阅、风格卡、批量问题列表 |

### 3.1 场景 A：技术规范精简

作者选中「构建适配需要对原有软件进行一定程度的调整……」，点击 `精简表达`。AI 在原文附近产生候选：

> 构建适配包括编译参数调整、依赖库替换及操作系统兼容性处理。

界面将删除、增补部分高亮。作者比较后接受；未选中的相邻段落不变化。建议应说明「保持技术事实、删除冗余表达」，不得将条件性语言改成确定性承诺。

### 3.2 场景 B：整章诊断、局部修改

作者指示：「检查第 4、5 章的衔接，指出问题；只修改 5.2 节。」Agent 可以读取指定范围及相关上下文，先在侧栏输出问题清单，仅对 5.2 节生成候选补丁。若无法安全定位，停止并询问用户；不得扩大写入范围。

### 3.3 场景 C：书籍长期创作

作者为《代码之上》建立项目，为「讲给非科班 AI Coder」配置文风：通俗、准确、适量举例、不堆砌术语。多次拒绝「营销式、夸张式表达」后，系统提示生成一条偏好候选；作者确认后，新章节的建议遵循该偏好。

### 3.4 场景 D：对比几个句式

作者对一句话提出「更简练、偏文学、保留原句节奏」的要求，得到 2～3 个候选版本。候选保持临时状态，作者能够试听（未来）、比较和一键保留，而不是反复覆盖原文。

## 4. 交互原则

### 4.1 三层交互

| 层次 | 入口 | 输出位置 | 默认权限 |
| --- | --- | --- | --- |
| L1 直接编辑 | 键盘、鼠标、常用格式操作 | 中央编辑区 | 用户直接写入 |
| L2 行内 AI | 选中文本、快捷键、浮动工具条 | 选择范围附近的建议卡 | 只生成建议 |
| L3 Agent 深度协作 | 侧边对话、引用段落/章节 | 侧栏诊断与定位到原文的建议 | 只读分析；变更逐条确认 |

### 4.2 主界面信息架构

- 顶部：文档标签、标题、保存状态、模式切换、全局搜索和设置。
- 左侧可收起：文件树、最近文档、项目入口。
- 中央：主编辑区，单栏宽度可调，编辑与实时预览同区；可切 Markdown 源码模式。
- 右侧可收起：文档大纲、Agent 对话、问题清单、修订历史（标签页切换）。
- 选区附近：轻量 AI 菜单。初始不常驻大量图标，避免干扰。
- 底部状态：字数、阅读进度/光标位置、编码与保存状态、正在运行的 AI 任务。

### 4.3 写作模式与审阅模式

| 模式 | 强调 | 行为 |
| --- | --- | --- |
| 写作模式 | 连续输入、低干扰 | 弱化 AI 提示；只保留主动快捷键入口；支持聚焦段落/打字机滚动 |
| 审阅模式 | 识别问题、逐项决策 | 展示诊断、变更差异、建议定位与接受/拒绝 |

**禁止**在每输入一个字后自动请求大模型。实时语法检测若后续加入，也要可暂停、可限频、可关闭。

### 4.4 选区与边界

- 无选区：可请求续写或根据光标前后文提供建议；明确显示插入位置。
- 有选区：默认只修改选区；用户可显式选择「整段」「当前章节」。
- 允许 Agent 获得更宽阅读上下文，不自动获得更宽写入权限。
- 文档在生成过程中若发生编辑，建议标记为过期，需重新定位或重新生成；不得盲目套用。
- 所有候选都能取消，应用后能撤销；拒绝建议不改变文档。

## 5. 功能需求清单

### 5.1 Markdown 核心编辑（V0.1 计划范围）

| P-003 | Markdown 实时编辑与源码模式 | 标题、列表、引用、链接、代码块、表格、图片在两种模式可编辑 |
| P-004 | 文档大纲与跳转 | 标题层级实时更新；点击能定位正文 |
| P-005 | 编辑基础能力 | 撤销/重做、查找/替换、快捷键、字数、缩放与聚焦模式 |
| P-006 | 本地文件树与最近文档 | 可打开单文件或文件夹；文件外部变更时提示重载/冲突 |
| P-007 | 内容保真 | 无编辑时不无故重写 Markdown；行尾风格、Front Matter、中文标点与代码围栏不丢失 |
| P-008 | 基础图片与相对路径 | 相对图片可预览；引用路径在保存时不被错误改写 |

### 5.2 行内 AI（V0.1 计划范围）

| ID | 需求 | 最小验收条件 |
| --- | --- | --- |
| P-101 | 选区调用 AI | 通过快捷键或选区菜单发起局部任务 |
| P-102 | 快捷意图 | `润色`、`精简`、`扩写`、`保持原意`和自定义指令 |
| P-103 | 可审阅建议 | 建议与原文同时可见；删除/新增高亮；不直接覆盖正文 |
| P-104 | 接受/拒绝 | 只更新目标范围；可撤销；拒绝不影响正文 |

| P-107 | 多候选比较 | 支持至少 2 个候选，并在当前修改位置预览其差异 |
| P-108 | 编辑目标约束 | 精简不得默认添加新事实；对结构内容（表格/链接/代码块）给出受限提示 |

### 5.3 Agent 与风格（V0.1 计划范围）

| ID | 需求 | 最小验收条件 |
| --- | --- | --- |
| P-201 | 侧栏对话 | 可针对当前文档和选择范围问答；不同请求明确上下文范围 |
| P-202 | 引用回跳 | Agent 答案可关联文档位置，点击跳转并突出对应段落 |
| P-203 | 范围可见 | 发起调用前可查看当前任务将发送哪些文本与额外指令 |

| P-205 | 风格卡 | 每个项目可维护目标读者、口吻、术语偏好、禁用表达与修改约束 |

| P-207 | 会话隔离 | 聊天记录按文档/项目区分，不无提示跨项目混入上下文 |

| ID | 需求 | 最小验收条件 |
| --- | --- | --- |

| P-302 | 元数据独立保存 | AI 任务、建议、聊天、风格及快照不嵌入用户 `.md` 正文 |

### 5.5 第二阶段（原 V0.2 SHOULD，顺延 V0.3）

> 版本调整（已确认）：V0.2 已定义为跨平台里程碑，本节功能顺延至 V0.3。V0.2 的平台支持范围见 [V0.2 跨平台计划](./v0.2-cross-platform-plan.md)。

- P-401：章/节级的全文结构与逻辑检查，提供「问题—证据段落—建议」列表。
- P-402：专业术语表，检查术语统一、禁止词、首现定义。
- P-403：书籍/项目的跨文档检索与引用；不默认将全项目上传模型。
- P-404：风格反馈记录、偏好候选提炼、用户确认后存入风格卡。
- P-405：更完整的段落版本对比、分支候选、修订批量处理。
- P-406：导出 HTML、PDF、DOCX（先定义模板与保真范围）。

### 5.6 长期方向（V0.3+ LATER）

- 可审计的自进化写作 Agent（候选规则—独立验证—用户确认—应用—回滚）。
- 多文档研究助手与有来源的事实核验；引用和缺失证据提示。
- Skills/MCP 扩展接口、作者自定义工作流；对外部工具采取独立授权。
- 多 Agent 的角色化协作（逻辑编辑、语言编辑、事实审查、审校），但不自动合并改动。
- 跨设备同步/多人审稿/出版排版/移动端作为独立项目评估。

## 6. 关键数据对象与状态

| 对象 | 用途 | 主要字段（概念） |
| --- | --- | --- |
| Document | 当前本地文档 | documentId, path, encoding, lineEnding, lastDiskHash, modifiedAt |
| Project | 本地文件夹范围 | projectId, rootPath, documentList, styleProfileId |
| SelectionAnchor | 定位原文 | documentId, revisionId, from/to, selectedTextHash, blockContext |
| AgentRequest | AI 调用 | id, intent, promptVersion, readScope, writeScope, providerId, status |
| Suggestion | 待审改动 | id, requestId, anchor, originalText, candidateText, explanation, status |
| StyleProfile | 写作偏好 | audience, tone, preferredTerms, forbiddenTerms, constraints, version |
| RevisionSnapshot | 恢复点 | id, documentId, parentRevision, contentHash, createdAt, source |

建议状态：`created → generating → ready → accepted/rejected/stale/canceled/failed`。任何失败状态不触发文档写入。

## 7. 非功能需求与质量门槛

| ID | 指标/约束 | V0.1 目标与测法 |
| --- | --- | --- |
| N-01 数据安全 | 原文为第一优先级 | AI 调用失败、断网、应用崩溃后不得静默覆盖原文；故障演练覆盖关键路径 |
| N-02 可恢复性 | 关键修订可撤销 | AI 应用前建立恢复点；应用可一键撤销；重启后可查看快照 |
| N-03 编辑流畅度 | 日常写作无明显阻滞 | 5 万中文字普通文档连续输入不明显卡顿；记录机器配置和实际延迟 |
| N-04 大文档可用性 | 不因篇幅失控 | 10 MB Markdown 可打开并滚动；超大文档明确性能提示 |
| N-05 一致性 | 只改授权范围 | 自动测试验证补丁目标范围之外文本字节/语义不改变 |
| N-06 兼容性 | Windows 首发；V0.2 跨平台 | V0.1：Windows 11 x64 主测，Windows 10 另列支持矩阵；V0.2：macOS 13+、Ubuntu 22.04/24.04 LTS x64，详见跨平台计划 |
| N-07 隐私 | 用户控制上传 | 仅显式 AI 请求向配置的模型提供本次上下文；调用前可检查范围 |
| N-08 可观察性 | 可定位故障 | 记录请求 ID、耗时、错误分类；日志不写 API key、完整私密文档正文 |
| N-09 可访问性 | 键盘优先 | 主要编辑、建议接受/拒绝和焦点切换可由键盘完成 |

目标是研发验收门槛，具体性能阈值应在原型测试时根据目标硬件建立基线，不将未经测量的结果描述为已实现。

## 8. 优先级原则与 V0.1 验收

**P0**：Markdown 无损编辑、保存与恢复、行内 AI、差异审阅、权限范围控制、模型配置与错误保护。  
**P1**：多候选、风格卡、文档 Agent 对话、来源记录与基本大纲。  
**P2**：跨文档一致性、长期学习、复杂导出、多端同步。

发布 V0.1 必须完成以下完整用户旅程：

1. 首次启动设置主题与模型（模型可稍后配置）；打开已有 Markdown 文件。
2. 离线情况下创建、编辑、保存、关闭、重新打开，内容不变化。
3. 选择中文段落，调用 `精简表达`，查看候选与 Diff，拒绝一次、接受一次。
4. 对同一段落生成两个备选；原文保持，直到用户明确选择。
5. AI 生成期间人工修改目标段落；旧建议标记 stale，不允许直接覆盖。
6. 配置项目风格卡，重新生成建议，能观察到风格约束进入请求。
7. 在 Agent 侧栏分析选中段落，点击答复引用回跳正文。
8. 模拟断网、请求取消、保存失败、文件外部变更；文档内容仍可恢复。

## 9. 商业化与竞争策略（非 V0.1 研发范围）

- 起步人群：经常编辑规范、方案、论文、长文的专业作者；他们对「不改变原意」与「可审阅」最敏感。
- 产品价值指标不应仅统计生成字数；重点观察保留修改率、修改复用率、用户编辑时间节省、无损率与主观可控感。
- 潜在商业模式：基础编辑器 + BYOK AI；后续提供高级智能审校、团队风格库和项目知识能力。具体定价、许可与商标另行论证。
- 竞品观察：Typora、iA Writer、Lex、Grammarly、Obsidian 已覆盖 Markdown 写作或部分 AI 改写。Vesrio 的差异点应是「原位、可控、保真、长期风格与专业文档协作」的组合，而非宣称最先实现 AI 改写。

## 10. 产品风险与策略

| 风险 | 影响 | 策略 |
| --- | --- | --- |
| Markdown 实时编辑损伤源码 | 数据可信度下降 | 将 `.md` 视为真源；黄金样本往返与差异测试 |
| 生成建议覆盖新编辑 | 丢字或误改 | 文档 revision + 选区 hash 双重校验；过期即禁止应用 |
| AI 虚构事实 | 专业文档不可信 | 默认编辑类任务「保持事实」；对新增事实标注并要求核实 |
| 模型输出破坏结构 | 表格/链接/代码异常 | 初版限制编辑范围；结构校验，不安全结果只作为参考文本 |
| 用户风格被 AI 同质化 | 作者失去主体性 | 手动接受、风格卡、提供多候选、无自动应用 |
| 私密文档泄露 | 重大隐私风险 | 本地优先；可预览发送内容；秘钥系统安全存储；日志脱敏 |
| 首版功能膨胀 | 工期失控 | P0 > P1 > P2，跨文档和自进化明确延后 |
